    Lire la transcription de la démonstration
    1. Charger le dossier d’exemple. Le brief distingue visiteurs, communication et équipe web ; les sources restent à vérifier.
    2. Ouvrir la première source et consigner une note de vérification. La source est déclarée revue pour le cas de démonstration.
    3. Compléter le responsable du premier support et enregistrer sa nouvelle version.
    4. Demander une relecture. Indiquer un relecteur et une décision explicite pour valider cette version.
    5. Modifier ensuite le contenu : une nouvelle version est créée et la validation est retirée. L’historique garde la version précédente.
    6. Consulter le calendrier puis exporter le tableau de production. Le support modifié reste un brouillon.

    Ce que j’ai développé

    Le système derrière les supports.

    Une logique de production

    Un modèle de données relie brief, publics, sources, supports et dates. Les règles contrôlent les conditions de validation ; une modification de contenu, de brief ou de source retire les validations concernées.

    Des outils simples

    HTML, CSS et JavaScript natifs, modules ES, formulaires accessibles et stockage local du navigateur. Exports JSON, CSV et Markdown. Capture de démonstration avec Playwright et FFmpeg ; contrôles de navigation et d’accessibilité automatisée avec Playwright et axe.

    Un périmètre explicite

    Pas de collaboration simultanée, de compte, de signature authentifiée, de vérification automatique des sources ou de publication sur les canaux. Une réimportation exige une nouvelle revue. Aucune mesure de gain de temps n’a été réalisée.
